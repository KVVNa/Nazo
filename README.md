# 宇宙船ミステリー（仮題）— Phase 3 試作

iPhone の縦画面で遊ぶ、宇宙船の推理ゲームの試作です。プレイヤーは船長として司令室から乗員に方針を与え、届いた報告と証拠から事件の原因を突き止め、仮説と対処を提出します。

- **航海モード（Phase 3）**：調査船〈ケストレル〉で、建設中の入植地がある惑星〈ハース〉（HD 137010 b）へ向かう62日の航海。固定の乗員8人と、プロローグ・出港前夜の顔合わせ・5つの事件・事件の合間の会話と手当て・到着と報告書の署名までを通して遊べます。死んだ乗員は戻りません。
- **組み立て式の工作事件**：犯人・動機・目的（盗む／消す／複製する）・陽動の手口（偽の火災警報／区画の停電／換気の逆流）・部屋への入り方（他人のカード／ドア記録の書き換え／共用番号）・時計のトリック・目撃者・アリバイの記録を、毎回部品から組み立てる。作業着の色、役目ごとの手袋や鍵、アリバイの記録を重ねて犯人を一人に絞る推理になる。単発では「事件を選ぶ」の13番、航海では第3〜5話の候補に入る。
- **単発の事件**：事件の型12種（事故・故障4、工作・犯罪4、未知の現象4）と組み立て式。毎回、乗員6人の顔ぶれ・関係者・時刻・証言者・通信断の区画がシードで変わり、検証器を通った事件だけが出てきます。

- 静的な Web アプリ（TypeScript + Vite、フレームワークなし）と手書きの Service Worker で動きます。
- 一度読み込めば、機内モードでも起動できます。
- 外部フォント、CDN、生成 AI の API、サーバー処理は使っていません。

## 起動手順

Node.js 20 以上が必要です（22 で確認済み）。

```sh
npm install        # 依存を入れる
npm run dev        # 開発サーバー（http://localhost:5173/）。Service Worker は動かない
npm test           # 単体テスト（全12事件の生成・検証・解決、再現性、情報の秘匿、対処の違い、判定、航海モード）
npm run build      # dist/ に公開用ファイルを作る（型チェック → ビルド → sw.js 生成）
npm run preview    # ビルド版を http://localhost:4173/ で確認
npm run e2e        # ビルド版を iPhone 13 相当の画面で通し試遊（第1話の解決、全12事件、オフライン起動、航海モードの最初から最後まで）
```

同じ Wi-Fi の iPhone から開発版を見るには `npm run dev -- --host` を使い、表示された `http://192.168.x.x:5173/` を Safari で開きます。ただし Service Worker は HTTPS でしか動かないので、オフライン確認は下の GitHub Pages 版で行ってください。

## GitHub Pages で公開する

1. GitHub で新しいリポジトリを作り、このフォルダの中身を `main` ブランチに push します。
   ```sh
   git init && git add . && git commit -m "Phase 1 試作"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```
2. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
3. push のたびに `.github/workflows/deploy.yml` がテストとビルドを行い、公開します。完了すると `https://<ユーザー名>.github.io/<リポジトリ名>/` で遊べます。この URL を友人に渡してください。

`vite.config.ts` の `base: './'` により、リポジトリ名のサブパスでもそのまま動きます。

## iPhone でのオフライン確認手順

1. Safari で公開 URL を開き、タイトル画面が出るまで待ちます（この時点で全ファイルがキャッシュされます）。
2. 共有ボタン →「ホーム画面に追加」。以降はホーム画面のアイコンから起動します。
   - ホーム画面に追加しないと、Safari は7日間使わなかったサイトの保存データを消すことがあります。
3. ホーム画面のアイコンから一度起動し、タイトル画面が出たら閉じます。
4. コントロールセンターで機内モードをオンにし、Wi-Fi もオフにします。
5. ホーム画面のアイコンから起動します。タイトル画面 →「新しい事件（ランダム）」→「司令室へ」まで進めればオフライン動作は正常です。
6. 更新を公開したあとは、オンラインで起動すると新しい版に切り替わります（反映されないときはもう一度起動してください）。保存データ（航海の進行を含む）は localStorage にあるので、更新で消えることはありません。

## 更新ファイルの反映（ブラウザからアップロードする場合）

受け取った zip を展開し、中のフォルダとファイルをリポジトリの「Add file → Upload files」にまとめてドラッグして Commit します。同じ名前のファイルは上書きされます。

- `.github` のように名前が「.」で始まるフォルダは、ブラウザのアップロードでは取り込まれません。ワークフローを変えたときは、該当ファイルを「Create new file」で作り直してください。
- アップロードではファイルを消せません。不要になったファイルは、中身を空にした同名ファイルで上書きしてあるので、そのまま残っていてもビルドは壊れません。

## 遊び方（試作版）

### 航海モード

- **タイトル →「新しい航海を始める」**。航海番号を入れると同じ事件の並びで遊べます（空欄ならランダム）。途中でやめても「航海を続ける」から再開できます。
- **プロローグと出港前夜**：画面をタップすると一行ずつ進みます（「すべて表示」で飛ばせる）。出港前夜は乗員8人が一言ずつ話し、船長の返事で最初の信頼が少し変わります。
- **5つの事件**：出港3・16・29・44・61日目。段階ごとに起きやすい事件が決まっています（出港直後の事故、深宇宙の現象、小惑星帯、恒星スイングバイ、到着前夜の人間の事件）。事件の中身は単発と同じ遊び方です。
- **事件の合間**：まず短い一場面（死者を悼む、関係人物への反応、船の暮らし）。できることは3つまで：乗員と話す（航海が進み、信頼が深まるほど踏み込んだ話になり、隠し事が分かる）、船体を修理する（予備部品を使う）、負傷者を手当てする（医療品を使う）、全員を休ませる。話の中で手を打っておくと、その乗員が起こすはずだった事件が起きなくなることがあります。事件で拘束した乗員は、拘束を続けるか解くかを選べます。
- **死亡・健康・信頼・船体の傷みは持ち越し**。予備部品と医療品は限られていて、救難信号の事件で採掘艇を救うと補給が届く。死んだ乗員は戻らず、欠けた機関・医務の役目は残った乗員が代わりに務めます。
- **到着**：実測値を見て、報告書に何を書いて署名するかを選びます。航海の中で分かったことによって、添えられる資料や、送信を止められるかどうかが変わります。結末と航海の評価（事件の解明・生きて着いた乗員・報告書）が出ます。
- 乗員名簿（合間の画面と事件中のメニュー）で、人物像と分かった隠し事を見返せます。

### 単発の事件

- **タイトル**：「新しい事件（ランダム）」か「事件を選ぶ」で始めます。ブリーフィングに出る **事件番号**（例：`03-123456789`）を友人に伝えると、「事件番号で始める」から同じ事件を遊べます。

### 事件の中（共通）

- **船内**：見取り図（どの事件も同じ船）。通信が通る区画の乗員だけが表示されます。事件ごとに、どこかの系統（左舷・右舷・下層）が通信断になっていて、中の様子は分かりません。上の3つの計器は事件ごとに変わります（電力、CO₂、気圧、発症者など）。
- **乗員**：乗員を選んで方針を与えます（事件ごとの現場対応〔電源を復旧、生命維持を点検など〕／区画を調査／通信中継器を復旧／負傷者を救護／区画を警備／待機）。通信断の乗員への指示は保留され、通信が戻ったときに適用するか確認します。「話を聞く」「証拠を突きつける」もここから。
- **記録**：届いた報告の一覧です。通信断中の出来事は「通信断中（何時の出来事）」の印と判断の理由つきで、あとからまとめて届きます。
- **メモ**：考えを整理する自由なメモ帳です。証拠カードを並べ、2枚を順にタップして線を引く・消す、線に一言添える、自分のメモを貼る、ができます。ここに書いたことは採点に使わず、正誤も表示されません。
- **仮説**：原因の種類、具体的な出来事、出来事の順番、関係人物、根拠の証拠、対処（作戦）を選んで提出します。原因の候補・出来事・対処は、集めた手がかりから浮かんだものだけが選べます（浮かぶと記録に「新しい見立て」と出ます）。誤った見立ても手がかりから浮かぶので、候補があること自体は正しさの印ではありません。最大3回。正誤はその場では示されず、作戦の結果として現場に返ってきます。
- ▶進行で時間が進みます。船内画面以外を見ている間とシートを開いている間は止まります。重要な報告、確認要請、警報が届くと自動で止まります。

## 仕様書の「提案」から変えた点と理由

| 項目 | 変更 | 理由 |
|---|---|---|
| 時間の進み方 | 内部は 1 tick＝ゲーム内10秒の固定ステップ。既定は停止で、▶進行のときだけ進む。仮説を提出して船内に戻ると自動で進み始める | `seed + 初期状態 + 操作列` で再現するため、操作を tick 番号付きで記録している。作戦の発令直後は現場を見る場面なので自動で再開する |
| 仮説と対処 | 提出フォームの最後で対処（作戦）を1つ選ぶ。作戦は通信の届く乗員のうち適任者が引き受け、実際に現場で実行される | 仕様では対処の選び方が決まっていなかった。仮説のうち「原因」が合っているかで作戦の中身が変わる（例：原因を取り違えると漏れを封止せず、再遮断する） |
| 予備電源の表示 | 司令室の残量計は定格容量を前提にした推定値。予備セルを実測する（または交換する）と実測値に切り替わる | 真相（セルが半分しかない）を画面から漏らさず、実測という調査行動で初めて分かるようにした |
| 保存 | 事件中は自動スナップショット1枠（「続きから」専用、巻き戻し不可）。単発の事件は終了時に「事件記録に保存」でき、事件記録だけ書き出し・読み込み可能。航海モードは航海の進行を別枠に自動保存し、事件が終わった瞬間に結果を書き込む（やり直し不可） | iPhone の中断対策と、スナップショットを使ったやり直しの防止を両立するため。書き出しは Phase 1 から簡易版を入れた |
| 乗員の自律性 | 経験・信頼・性格から「自律度」を出し、高い乗員は危険な作業も自分の判断で行い理由を報告する。低い乗員は通信の届く場所まで戻って確認を求める | 仕様の「確認する／自分で動く」を具体化した |
| 負荷の切り離し | 予備電源の消費を約4割減らす | 半分にすると危機の緊張が薄れたため |
| 乗員の人数 | 単発の事件は6人（機関士・医務官＋4人を8職種から）。航海モードは固定の8人 | 単発は短く遊べるように。航海は人物を覚えてもらうために固定 |
| 部屋割り | 調査船〈ケストレル〉の固定の見取り図（13区画）。左舷：居住区・食堂・研究室・貨物室、右舷：通信室・医務室・生命維持室、下層：機関区・配電室・エアロック・水再生室。中継器は居住区・通信室・下層機関区 | 航海で同じ船に乗っている感覚を保つため。縦に長いので、小さな画面では見取り図をスクロールする |
| 事件の生成 | 完全自由な因果生成ではなく、手作りの型12種の変数をシードで振り、検証器で棄却・再生成 | 仕様どおり。文章の破綻を防ぐため、差し替えるのは名前・区画・時刻に限った |
| 組み立て式の事件 | 工作・犯罪だけを部品化した。目的9種 × 陽動3種 × 入り方3種（＋時計のトリック）× 犯人 × 目撃者 × アリバイ。航海の乗員は動機を2つずつ持ち、口調（丁寧／ぶっきらぼう）も証言に反映する。検証器に「必須証拠だけで犯人が一人に絞れるか」「誤った原因の候補がどれも客観証拠で否定できるか」を足した | 事故と未知の現象は、船の系統（電力・空気・通信など）を共通化してから部品化する |
| 航海の事件 | 同じ12種の型を、固定乗員で生成する。関係人物は人物像に合う乗員を優先し、動機などの文は乗員ごとの差し替え文を使う。「寄港」「太陽」は「到着」「恒星」に言い換える | 型を増やさずに、乗員の隠し事と事件をつなげるため |
| 資源 | 事件の合間は3枠で、話す・修理（予備部品）・手当て（医療品）・休息から選ぶ。船体は持ち越し。食料の配分はまだない | 判断の種類を増やしつつ、画面を増やしすぎないため |

## 構成

```
src/
  core/      型、乱数（状態を GameState.rng に保持）、時刻
  voyage/    航海モード：固定乗員8人、プロローグ・会話・到着の文章、航海の進行（持ち越し・代役・事件の選び方・評価）
  cases/     事件の型12種（真相→証拠→証言、危機の進み方、作戦）
  gen/       事件の書式、乗員の候補、生成と再生成、静的検証器（名前・時刻・区画の辻褄を含む）、動的検証
  sim/       船の部屋グラフ、tick 進行、作業の効果、報告の配送、作戦、プレイヤー操作
  ai/        乗員の行動AI（本人の知識・観測・方針だけを受け取る）
  judge/     構造化仮説の部分判定、事件結果
  view/      プレイヤーに見せてよい情報だけの ViewModel
  ui/        画面（DOM）。ViewModel と進行役（game.ts）だけを使う
  render/    見取り図（Canvas）と、パレット＋部品で生成するピクセル肖像
  save/      スナップショット・事件記録・航海の進行・設定（localStorage、スキーマ版付き）
scripts/     sw.js 生成、アイコン生成
tests/       単体テスト
e2e/         iPhone 画面での通し試遊スクリプト
docs/        事件一覧と生成・検証のしくみ、航海モードの人物と筋（ネタバレ）
```

真相と知識の分離は型とモジュールの境界で行っています。`ai/` は `gen/`・`sim/`・真相を import しないこと、`ui/` は `gen/`・`judge/`・`sim/sim` を import しないことをテストで確認しています。通信断の乗員の位置・行動・健康は ViewModel に入りません（最後に確認できた値だけ）。

## 既知の未実装項目

- 航海モードの資源は船体・予備部品・医療品だけ。食料や士気の配分はまだない。
- 乗員どうしの関係（誰と誰が親しいか）は会話の文章にだけ出てくる。事件中の行動には反映していない。
- 型の事件（12種）の証言・後日談は型の文章で、固定乗員の口調にはまだ合わせていない（動機・告白など一部だけ差し替え）。組み立て式の事件の証言は口調に合わせている。
- 組み立て式は工作・犯罪だけ。事故と未知の現象は型の中身（因果の筋書き）が手作りのまま。シードで変わるのは関係者・時刻・証言者・通信断の系統・乗員の居場所（単発では乗員の顔ぶれも）。
- 事件の長さはまだ短め（正しく進めるとゲーム内20〜50分）。1事件20〜40分（実時間）の目標はプレイテストで調整する。
- 見取り図で乗員を直接ドラッグして移動させる操作はない（方針で動く）。区画の施錠・損傷による通行条件の変化は未実装。
- 効果音は WebAudio の合成音のみ。BGM なし。手描きのピクセル素材はない（`src/render/sprites.ts` を差し替えれば入れ替えられる）。
- iPhone 実機での確認は未実施。Chromium の iPhone 13 相当の画面で通し試遊とオフライン再起動を確認済み。

- 見取り図を固定にしたため、以前の版の「事件の途中」の保存（単発・航海とも）は引き継がない。航海モードの途中だった場合は、その話を最初からやり直す。事件記録と航海の進行は引き継ぐ。
